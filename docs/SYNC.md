# 一键获取与上传

下载 [XMindSync.exe](https://github.com/duohaocui-eng/xmind-ai-workspace/releases/latest/download/XMindSync.exe)，双击运行，选择已有本地工作区即可。程序不会定时上传或自动同步，只有点击按钮才执行对应操作。

## 首次准备

电脑上已能正常拉取 / 推送工作区：直接选择该文件夹，复用现有 SSH 密钥或 HTTPS 凭据，无需登录新的服务。

尚无本地工作区：先用仓库的 Use this template 建立自己的副本，然后使用 Git 客户端将自己的仓库克隆到电脑。可用 [GitHub Desktop](https://desktop.github.com/) 完成，不必输入 Git 命令。同步程序需要能找到 [Git](https://git-scm.com/downloads)；如电脑未安装，请先安装。不要把下载 ZIP 的文件夹当作已克隆仓库。

将同步程序放在下载目录或常用程序目录即可，不必放进导图仓库。

## 日常只用两个按钮

- **获取云端更新**：检查云端，下载更新，显示涉及的导图。先保存并关闭相关 XMind 文档，完成后重新打开。
- **上传本地修改**：先在 XMind 中保存，再点击。程序自动提交和推送导图及目录索引，显示上传结果。

“刷新状态”只检查状态，不上传导图；“打开导图文件夹”直接进入本地工作区。第一次进入显示的是已有 Git 信息，点击刷新会重新检查云端。

程序还会保存最近选择的工作区。不存储密码或私钥。

## 遇到需要处理的情况

- **两边修改不同文件**：上传时会整合不冲突的云端更新并更新目录，然后推送。
- **两边修改同一文件**：停止覆盖，保留原仓库和双方文件副本，显示副本目录。对比并保留需要的版本后，通过 Git 客户端完成冲突处理，再继续同步。
- **本地尚有修改时点击获取**：先提示上传或另存，不覆盖本地修改。
- **有程序文件等其他修改、已暂存内容或其他待推送提交**：提示先处理，不会顺手提交这些内容。
- **上传中断**：本地已完成的提交会保留；网络恢复后重试。
- **认证失效或没有上游分支**：先恢复原来 Git 拉取 / 推送能力，再重试。

程序不能读取 XMind 内存里尚未保存的编辑，也不让已打开的文档自动刷新。

## 其他系统

macOS / Linux 或已有 Python 环境可执行 `python3 sync_app.py`；需要系统提供 Tk。Windows 可直接用打包程序，不需要 Python。

需要原来的本地读写菜单时，仍可运行 `run.cmd` / `bash run.sh`，这是可选入口。
